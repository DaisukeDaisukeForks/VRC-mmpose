# VRC MMPose — RTMW 2D + constrained pseudo-3D PoC
足首・つま先・踵を含む133点をRTMW-L/X 256×192で検出し、カメラ射線・本人の骨長・時系列・条件付きの床接地拘束から奥行きを推定する。撮影済み動画のみ入力し、映像や関節データはアップロードしない。
公開サイト: https://vrc-mmpose-video-lab.daisukedaisuke389137.chatgpt.site
公式MMPose: https://github.com/open-mmlab/mmpose
変換元Actions: https://github.com/DaisukeDaisuke/mmpose-actions/actions/runs/41360812832
モデル配布: https://huggingface.co/RabbitDaisuke/rtmw3d-webgpu-onnx/tree/2fc6f257743eb890a340a50bbaa3e46c5a313e83/rtmw2d
## 使い方
1. 「モデルを準備」で初期選択のRTMW3D-L FP32 GPU decoder約230MBを取得。SHA-256、バイト数、セッション作成と実際の初回推論を確認する。Cache Storageからの再利用時にもハッシュを照合する。
2. 動画を選択。全体・手動ROIでは人物検出器を取得しない。自動ROIだけRTMDet-s約40MBを追加する。
3. 通常再生か全フレーム解析で推論。2D信頼度の閾値、顔・手の表示、表示平滑化を調整できる。
4. 本人身長と画角、必要ならfx/fy/cx/cy・カメラ高・ピッチ・大腿/下腿長を設定し、「距離推定を有効にする」。未校正の3D表示は入力値を仮定するが、絶対カメラ/床座標を出力しない。
5. 単眼の奥行き初期解を「膝・腕が手前／奥」から選ぶ。単眼2Dから前後の解が一意に決まることは保証しない。
6. 同じトップ画面のモデル欄でL/X×8構成を選択できる。変更後はモデルを再準備する。FP32との差が大きい量子化版は選択肢に明記する。FP16やINT8を理由に高速と扱わない。
7. JSON/CSVで2D px・信頼度・相対推定3D・校正後のカメラ/床座標・時刻を保存する。計測ログにはモデルrevision/ハッシュと実効fpsを含む。
## 3D推定の実装
元動画の2D関節から射線[(u-cx)/fx,(v-cy)/fy,1]を作り、各関節の射線上の深度を最適化する。入力した身長・骨長と投影された複数の骨の長さから初期の人物距離を決め、骨長誤差のHuber損失と前フレームの骨盤相対深度を使う。骨盤の深度自体も更新し、前後移動を固定しない。
足首・つま先・踵も骨長拘束に含める。前フレームから床付近に留まり、画像上で低速の足に限って床拘束を加える。足の上昇時に床へ無条件で固定しない。顔・指の奥行きは対応する身体アンカーから補間し、独立した奥行き観測ではないことをdepthSourceに保存する。
3Dプレビューだけ骨盤中心・Y上の座標に変換する。校正後の床ビューは視点中心を毎フレーム人物へ追従させず、人物の移動を表示する。JSONでは2D観測と推定深度を区別し、depthAmbiguous=true、scaleCalibrated、depthMethodを記録する。
この方式はモデル推定3Dや多視点三角測量の実測ではなく、単眼の模擬3D。前後反転、遮蔽、短縮投影、本人の骨長仮定、カメラ校正誤差に影響される。骨長残差は精度保証や統計的な信頼区間ではない。
## 2D/3Dモデルの切替
初期選択は実験で差分基準内だったrtmw3d-l-fp32-gpu-decoder。同じNHWC＋GPU入力・出力バッファ再利用経路をトップ画面で使用し、毎フレームの読み戻しは133点と信頼度の2128 bytesに限定する。Graph Captureは使用しない。既存32構成と合わせて計33構成を選べる。利用者の実測はp50 35.7ms、p95 42.7ms、27.4fpsで、今回の公開環境で再計測した数値ではない。顔・手・足首・つま先・踵とモデルの相対Zを維持し、差分基準外のhead-gemm版は追加しない。
既存のRTMW-L/X 256×192（各8構成）に、RTMW3D-L/X 384×288（各8構成）を加え、既存32構成も同じトップ画面で選択できる。RTMW3Dではinput[1,3,384,288]、keypoints[1,133,3]とscores[1,133]を使用し、モデルの相対Zを模擬3Dソルバーで上書きしない。2D版の入力とSimCC復号も維持する。モデルを切り替えたら再準備が必要で、選択したファイルだけを取得・照合・キャッシュする。相対Zと骨盤の絶対距離は区別し、3D版でも絶対距離・床座標は校正値と骨長から別途推定する。
## モデルと実行エンジン
Actions成果物の公開revisionを固定し、全16構成のサイズ・SHA-256をdist/rtmw-models.jsに記録する。RTMW-L FP32は228801026 bytes、SHA-256 8b6fb439dd02b02b0f71edaac647c8818e2335083ba1b3abc103f852a7c7c8d8。入力float32[1,3,256,192]、出力simcc_x[1,133,384]とsimcc_y[1,133,512]。RGB/ImageNet正規化、SimCC比率2で復号する。3D出力が存在するとは扱わない。
onnxruntime-web 1.27.0 JSEPへユーザー提供のFP32累積パッチを適用する。WebGPUが通常経路、WASMは明示的診断のみ。初回の実推論はfpsから除く。元動画から192×256のROIを直接切り抜き、表示用映像の縮小をモデル入力へ流用しない。
従来HFのRTMW3Dファイルと既存比較ページは変更しない。InstantHMR関連ファイルは履歴として残すが、トップ画面からは読み込まない。
## 実行と確認範囲
Node.js 22以降でnode serve.mjsを実行し、http://127.0.0.1:4173 を開く。dist/をそのままSitesへ配信できる。
今回テストは追加しない。CIは配信JavaScriptの構文確認のみ。旧モデル用のテストファイルは履歴として残し、現在のアプリの受入判定には使用しない。クラウドブラウザでの視覚確認とbrowser-numericalは行わない。RTX実機の速度、姿勢精度、床接地の正確さ、SteamVR送出は確認済みとは扱わない。
