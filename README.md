# VRC MMPose — Phase 01
ローカル動画からRTMW3D-Xで133点の全身ポーズを推論する静的Webアプリ。モデルは`Soykaf/RTMW3D-x`、実行エンジンは`onnxruntime-web@1.24.3/webgpu`。動画や推論結果をアップロードしない。
## 使い方
1. 公開サイトをPCのChrome / Edgeで開く。
2. 「モデルを準備」を押す。初回はRTMW3D-X 369,330,857 bytesとRTMDet-s 40,309,222 bytesを取得し、SHA-256を確認してCache Storageへ保存する。モデルのセッション構築後に実際の初回推論も検査する。
3. iPad等で撮った動画を選択する。サンプル動画も同梱している。初版にカメラ入力はない。
4. 自動検出、手動ROI、映像全体のいずれかを選ぶ。手動ROIは入力映像をドラッグして指定する。
5. 「推論を開始」。通常再生では追いつかないフレームを間引き、全フレーム解析では指定fpsの時刻を順次処理する。入力動画の本来のfpsと、全フレーム解析のサンプリングfpsは別である。
6. 身長と画角、またはカメラ内部行列を設定して距離を校正する。骨長と相対Zを用いる単眼の概算であり、未校正時は絶対距離を出力しない。実距離精度やSteamVRへの追従品質は未検証。
7. JSON / CSVで関節・欠測・相対Z・校正状態・骨盤のカメラ/床座標を、計測ログで処理時間を保存できる。
## ローカル実行
Node.js 22以降。追加npmパッケージは不要。
```sh
node serve.mjs
```
`http://127.0.0.1:4173`を開く。`file://`ではES Modules、WebGPU、Service Workerが使用できないため、HTTPで配信する。localhost/127.0.0.1はブラウザの安全なコンテキストとして扱われ、Service Workerを利用できる。現在の初版は静的配信だけで足りるためWebSocketサーバーは追加していない。
## 実装
`dist/`がそのままデプロイ対象。ビルド不要。解像度を落とした全画面映像を別途生成せず、元フレームの人物ROIを288×384へ一度だけ変換する。人物検出器のみ640×640の入力を作る。人物は最大面積と以前のBBoxとの重なりで一人を選択し、関節で追跡、定期再検出する。見切れは仮想BBoxと黒パディングに対応する。
SimCCの深度の入力寸法は288。Zの復号は`(z_index / 2 / 144 - 1) * 2.1744869`。画像の高さ384をZの分母に使用しない。スコアはMMPoseと同じX/Yの最大値の小さい方を生値として保存し、欠測判定と表示用の信頼度を区別する。2D座標はクロップ前の元動画へ戻す。
距離は相対Z、内部行列、身長から推定した複数の骨長のロバスト損失を1次元最適化して求める。左右の大腿・下腿長は実測入力も可能。しゃがみでBBoxの高さが変わっても、その高さを直接実距離に置き換えない。床の高さとピッチはカメラ外部姿勢の入力値から変換し、ジャンプ時の足を床に固定しない。単眼推定の不確かさ表示はヒューリスティックで、統計的に校正された信頼区間ではない。
RTMW3D-Xは選択したWebGPUで推論し、RTMDet-sのNMSを含む人物検出はWASMで実行する。WebGPUがない場合のCPU実行は明示的なWASM診断モードのみ。通常再生の実効fpsと、1フレーム処理時間からの理論的スループットは分ける。初回ウォームアップは計測から除外する。GPUメモリはブラウザから正確に計測できず、測定済みとは表示しない。
## 検証
`verification/onnx-cpu.json`は元のONNXをCPUで実行した実測結果。動画の0・2・5秒から人物を検出し、133・125・118点が閾値0.30を超えることを確認した。これはGPU性能や60fps達成の証明ではない。`verification/decoder-fixture.json`はその実出力の最大位置と公式式による復号値。
GitHub Actionsの`Verify Phase 1`で構文、ROI、SimCC復号、距離の幾何、フィルターのシーク時リセット、実ONNXのハッシュ・出力形状・人物動画の推論を検査する。`Deploy GitHub Pages`は手動実行用。現在の主な公開先はChatGPT Sitesで、Pagesはリポジトリ側で有効化した後に実行する。非公開リポジトリの可否はGitHub契約と設定に依存するため、リポジトリを勝手に公開へ変更しない。
今回の作業環境ではブラウザ操作基盤が接続できず、実ブラウザ上のWebGPU動作・キャッシュ再起動・見た目は未検証。RTX 5060 Ti 8GBでの実効60fpsとVRAM8GB適合は未実測。実機・距離マーカーを用いた誤差測定、床接地推定、複数カメラ、WebRTC、ずんだもんアバターのリターゲット、Codex sandboxの境界probe、SteamVR/VRChat送出はこの初版で完了したと扱わない。
## キャッシュと通信
モデルはHugging Faceのrevision固定URLから公開フェッチし、取得後にSHA-256照合する。キャッシュからの再読み込みでも照合する。容量・権限不足でも推論は継続し、永続化できたと偽らない。ローカルONNXも同一のSHA-256を要求する。動画はBlob URLで端末内に保持し、ネットワークへ送信しない。モデル・実行エンジン・Google Fonts取得時には外部通信が発生する。
Service Workerは静的アプリと取得したORTの実行ファイルをキャッシュする。初回準備後は同じオリジンでモデルとORTを再利用できる。オリジンごとにCache Storageは分離されるため、Sites、GitHub Pages、127.0.0.1はキャッシュを共有しない。完全閉域の保証には実際の端末ファイアウォールとWAN遮断の検証が必要。
